# 创建新番定时任务

仅创建或修改任务时读取本文件。已触发的运行读取
[scheduled-run.md](scheduled-run.md)。资源选择沿用 SKILL.md 的新番默认／老番选项策略；
任务正文只保存范围和覆盖条件。

## 自然语言入口

用户调用本 skill 并说“给《作品》安排每周五 22 点的定时追番”时，直接执行下面的
创建流程，不要求用户提供模板、track_id 或重复整套规则。作品和时间也可从当前
对话中已明确的上下文取得；只在无法唯一确定作品范围或时间时补问。
创建请求本身不代表立即运行下载；用户同时要求“现在先执行一次”时，创建并绑定
成功后再进入检索流程。

## 创建前的模式门禁

在读时间、填模板或调用 `automation_update` 前，先确定作品生命周期和任务形态：

1. **已完结 + 未指定未来时间**：直接进入一次性检索/导入，不创建追番记录或周期任务。
2. **明确只执行一次，或已完结作品指定未来时间**：创建一次性导入任务；仅交付成功
   或用户取消后删除。失败与补查按下方一次性任务规则处理。
3. **连载或尚未开播 + 明确周期**：才创建周期追番任务。

作品生命周期以已绑定 v3 状态和官方/播出方证据为准；当前没有下一集不证明完结。
状态未知时核实证据，同时保留用户明确的一次性意图。

## 创建与参数填充

1. 读取 SKILL.md，先执行上面的模式门禁，再 inspect 已有记录；核实作品年份、季／part、provider 绑定和
   集数映射。使用已验证别名搜索，不能通过模糊首项绑定作品。周期追番的新记录经 watch create
   建档；未知字段保留未知，有真实歧义才询问。计划尚未开播不妨碍建立将来任务，
   但不凭日期推断已发布。身份未解决时停止创建。
2. 检查现有自动化的完整 prompt 和身份：相同目标和用途优先复用。不同季、part、
   下载模式或硬限制不是同一用途，不能覆盖。只有用户明确要求新建重复任务才重复。
   用户明确时间优先，默认 Asia/Shanghai；未指定时间先核实官方/播出方首播或配信
   时刻，以可验证的首发可用时刻后 2 小时作为建议检查时间，并在创建结果中说明。
   多个不能消歧的时刻或无可靠时刻才询问；不把日本深夜日期直接当北京时间。
3. 周期任务采用下方五行模板；一次性任务按末节调整入口、范围和时间。
   明确要求精简的旧任务使用对应格式；固定身份、质量与字幕、交付模式。
   默认 browse 1–2 GiB、允许向上兼容、中文软偏好、加入 qBittorrent。
   用户只查/磁力/不下载时明确写“仅检查/仅返回磁力，不下载、不更新进度、不自动删除”。
   不把运行流程复制进 prompt；执行时按技能入口加载对应步骤。
4. 自动下载首次配置或客户端路径／用户／网络类型变化时，先按
   [client-readiness.md](client-readiness.md) 核对无人值守准备情况；已有有效授权不重复询问。
   可以保存计划，但环境未核实或仍有系统弹窗时，明确说明尚未确认可无人值守。
   使用宿主提供的调度工具创建或更新；Codex 中使用 automation_update。
   周期任务默认在当前聊天创建 heartbeat；用户已指定可访问的追番聊天时使用该聊天。
   聊天 ID 必须来自当前用户的实际环境，不复用示例或其他安装者的 ID。
   一次性任务使用工具支持的单次计划，不套用周期 heartbeat。
   用户后续明确指定其他聊天或独立任务时，以新指示为准。
   保留已有任务 kind/归属，除非用户要求迁移；沿用目标聊天/任务当前选择的模型。
   其他 Agent 需提供等效的调度创建、读回和删除能力，以及可供绑定核验的配置；
   未适配这些接口时只使用交互检索/下载，不声称已创建定时任务。
   按工具契约完整保留其他字段。运行反馈沿用 scheduled-run.md 的
   无变化静默和简短通知规则，不把通知策略设置混进任务正文。
5. 创建返回后读回实际 ID、最终 prompt 和计划。SHA-256 使用最终保存的 prompt
   UTF-8 内容，不能自己归一化空白；不把自身 ID/hash 回填 prompt，避免循环变更。
   周期追番核验全部目标，按 [completion.md](completion.md) 调用 bind-automation。绑定失败
   明确报告，首次交付前修复；scope 变化须重新审阅全部范围，不能盲目重绑后删除。
6. 保存常规计划和创建结果。确认创建不等于已经下载；只有工具返回/读回确认后才
   报告已创建。结果不确定先读回查重，不能再造一个任务。

## 周期追番五行模板

```text
使用 $find-nyaa-anime-release，按 references/scheduled-run.md 执行。
范围：{{作品、年份、必要的季/part/阶段、track_id；必要的编号映射}}。沿用该 track 的身份与别名，不扩展范围。
常规时间：{{用户约定的周期和时刻}}，Asia/Shanghai。
条件：browse，优先 1–2 GiB、允许向上兼容、中文字幕软偏好。
模式：最新未处理正片，授权加入 qBittorrent；其余执行技能默认规则。
```

这是实际保存到自动化的正文格式，不把创建步骤附在正文后面。显式时区、体积、
字幕或交付要求直接替换对应行；只查/磁力/不下载模式按步骤 3 覆盖默认下载授权。
补查、恢复、回执、完结清理、临时文件及反馈规则只维护在技能对应参考文件中，
不粘贴进每个任务。范围行仅保留辨认本部和编号所需的信息，不重复全部别名。
任务标题用“追番：{{作品短名}}”；最终只简短确认作品、实际计划和必要例外，
无需向用户重发保存的完整正文。

身份中的未知字段保持未知。已有 track_id 可引用持久化的身份与别名，
只补充区分季/part/阶段所需的信息，不粘贴内部命令、回执协议和恢复细则。
已有任务的 prompt 缩短会改变 scope hash；必须读回并按 completion.md
审阅全部目标后重新绑定，不能只改文字就声称迁移完成。
维护本模板不自动迁移现有任务，也不改变其模型或归属。

## 一次性整季任务

一次性整季请求在模式行指定“整季”，运行入口改用 retrieval-workflow.md 的整季
分支及 [package-review.md](package-review.md)；不套用单集最新集审阅或每周补查 planner。
范围行保存已核实作品及整季范围，无需创建单集追番 track 或绑定虚构的 track_id；
时间行保存实际单次执行时间，任务标题用“一次下载：{{作品短名}}”。
使用单次计划，客户端接受完整合集并持久化匹配回执才算交付成功。未找到资源或
临时检索失败按用户授权补查；老番需预先选定候选或明确授权按默认选择，
否则只报告选项并暂停交付。已发现资源但校验冲突时保存诊断、保留任务并通知，
不盲目重试，也不因失败或单次触发已用完而删除。修复后恢复原任务目标。
仅成功后或用户明确取消时删除自动化；次数耗尽则保留失败记录并结束补查。

“一次性整季”与“已完结作品的一次性导入”都不创建周期追番。前者处理整季资源，
后者按用户指定的集数/资源范围执行；若用户未指定未来时间，默认立即执行。
